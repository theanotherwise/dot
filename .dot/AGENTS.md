# Local Shell Customization Instructions

## Purpose and Location

This tracked file lives at `.dot/AGENTS.md` in the dot repository and at `~/.dot/AGENTS.md` in a home-directory installation. It documents how agents maintain the local ad hoc files beside it. Follow the project-wide instructions in [`../AGENTS.md`](../AGENTS.md) as well. Keep this instruction file tracked; the user's `adhoc_aliases` and `adhoc_functions` remain ignored and untracked.

## Local Ad Hoc Entries

When the user asks for a local, private, or ad hoc alias or function, put it in `adhoc_aliases` or `adhoc_functions` in this `.dot` directory instead of the tracked `aliases` or `functions`. Resolve the requested checkout first: in the home installation the local paths are `~/.dot/adhoc_aliases` and `~/.dot/adhoc_functions`; files in a separate workspace clone are not automatically loaded by the user's shell. Do not silently edit or copy entries into another checkout. Keep alias definitions in `adhoc_aliases`; put multi-step logic in `adhoc_functions`, use the `sc_helper_` prefix for new helper functions, and expose public command names through aliases in `adhoc_aliases`.

Before editing, inspect the relevant existing definitions in both the tracked and local files. Preserve unrelated entries, comments, file permissions, and symlinks; add a new definition or update the existing definition with the requested name instead of appending duplicates or replacing the whole file. Preserve the user's exact command names and quote arguments and paths correctly. Local definitions load after their tracked counterparts, so avoid accidental name collisions and override an existing command only when requested. If the local files are missing, create them through `sc_helper_adhoc_init` for the selected `.dot` directory without running setup or the installer. Both files must remain ignored and untracked; never force-add them, copy their contents into tracked files, or use `assume-unchanged` or `skip-worktree` to hide edits to tracked files.

After editing, run `bash -n` on each changed ad hoc file. Run Git checks from the verified checkout root, which is the parent of this `.dot` directory: verify that `git check-ignore -v -- .dot/adhoc_aliases .dot/adhoc_functions` reports ignore rules and that `git ls-files -- .dot/adhoc_aliases .dot/adhoc_functions` is empty. Review only the requested changes without exposing unrelated local entries, and do not execute the added commands as a syntax check. Report the exact edited paths and checks performed. In a home installation, the next `bash -l` loads the entries; for an existing shell, provide the relevant `source` commands, loading `~/.dot/adhoc_functions` before `~/.dot/adhoc_aliases` when both changed. Ordinary `git reset --hard` and `git clean -fd` preserve ignored ad hoc files; never use commands that delete ignored files, such as `git clean -fdx`, as part of this workflow.
